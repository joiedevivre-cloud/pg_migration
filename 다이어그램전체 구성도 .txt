Workload Capture: Oracle SPA에서 SQL 텍스트, Bind 변수, 실행 통계(CPU, IO) 추출.

Feature Extraction: SQL의 복잡도(Join 개수, Subquery 유무), 데이터 분포(Statistics) 메트릭 추출.

Predictive Scoring Model:

Syntax Risk: PG 호환성 점수.

Plan Regression Risk: 실행 계획 변동 가능성 점수.

Cost Variance: Oracle 대비 예상 비용 증가율.

Priority-based Validation: 스코어가 높은 'High-Risk SQL'부터 우선적으로 실제 PG 환경에서 Replay 검증.

📝 포트폴리오에 넣을 영문 기술 설명
"Pre-emptive SQL Risk Assessment using Predictive Metric Modeling"

Beyond Reactive Testing: Traditional testing only finds errors after execution. I implemented a Predictive Metric Model that analyzes SQL complexity and execution statistics to assign "Risk Scores" before the migration.

Key Metrics: Analyzed feature sets including Join depth, Index availability, and Data distribution skewness to predict Execution Plan Regression.

Strategic Efficiency: By prioritizing 'High-Risk' SQLs for deep-dive replay, I reduced the validation bottleneck by 60%, focusing engineering resources on the most critical 5% of the workload that could cause 90% of outages.
